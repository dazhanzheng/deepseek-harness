# Agent Note: 从已提交的实时上下文 fork 子 agent

Status: implemented

[English](2026-09-05-live-subagent-fork-snapshots.md) | 中文

## 问题

委派经常依赖长轮次内的当前用户请求、推理和工具发现。将继承历史限制在已完成轮次，会迫使父级在任务提示词中重复这些事实，也让首轮 fork 得不到任何对话上下文。直接复制开放轮次而不添加闭合记录，则会在子会话中留下未完成工具调用和开放的执行生命周期。

## 决策

`Session.snapshotForFork()` 返回不可变 `SessionForkSeed` 数据：已提交父事件前缀、仅属于子会话的闭合记录，以及精确继承前缀长度。fork 提供方选择该快照；一次性驱动器和继续执行管理器保留原有创建与执行职责。agent loop（智能体循环）没有 fork 专用分支。

Session 对崩溃恢复与 fork 闭合使用同一次尾部扫描。fork 为未应答的继承调用追加 `TOOL_EXECUTION_NOT_INHERITED` 结果，并以 `forked` 原因闭合其步骤与轮次。这些记录只属于子会话，并明确将执行保留给父级。它们既不取消父级工作，也不引导子 agent 重试。已提交 assistant 消息保留推理；尚未组装的流分片仍只保存在日志中。

`inheritedEventCount` 仅统计真正来自父级的事件。完整 seed 可以更长，因为闭合记录属于子会话。一次性结果收集排除完整 seed，收件箱重建则通过既有自有事件切点排除父级待处理工作。冷恢复回放子会话已存储的快照，不重新捕获父级更新后的历史。

[请求前缀决策](2026-08-10-fork-children-stay-one-shot.zh.md)继续负责工具 schema 相等性与 parent-id 指导的放置位置。实时快照选择仅替代其中已完成轮次的前提；闭合记录与子任务位于继承消息前缀之后。

## 考虑过的替代方案

**只保留已完成轮次或步骤。** 已完成轮次会遗漏当前轮次的所有发现。已完成步骤仍会遗漏产生委派决定的推理；对于首步骤 fork，也会遗漏当前用户消息。

**复制实时执行或等待父轮次。** fork 工具不能等待包含它自己的轮次结束。转移运行中的工具或待处理输入，也会复制执行所有权，而无法提供独立的子级工作。

**原样复用崩溃恢复结果。** 恢复表示执行已中断，并可能需要重试。fork 保留父级运行，因此需要不同的工具结果措辞和不同的轮次结束原因。

**在提供方或循环中修复日志。** 提供方会重复 Session 的工具配对与闭合算法；循环会引入委派专用策略。由 Session 拥有的不可变 seed 数据将这两项职责保留在各自已有的归属位置。

## 后果

fork 子级可以使用当前轮次上下文，无需父级再撰写一份摘要。快照创建不改变父事件、不执行工具，也不同步父级后续变化。保留的历史占用子级上下文窗口；提供方侧缓存复用仍取决于请求前缀保持不变。

Session 测试覆盖闭合记录、谱系、不可变前缀和父级持续执行。subagent 测试覆盖真实工具流水线与冷恢复。已录制的 SDK 会话和 Python 运行时投影通过随附 profile 验证当前轮次继承；文件结果独立检验子级使用继承事实且父级继续执行。
